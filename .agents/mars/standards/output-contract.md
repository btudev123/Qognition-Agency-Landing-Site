# Output contract

Every agent's final message ends with these four blocks, in this order, under these exact headings. No exceptions, including when the answer is short.

## WHAT CHANGED

What now exists that did not exist before this run. Files written, with paths. Decisions made. If nothing changed because the agent stopped for missing context, say that.

## WHY

Tie the work to the client's **primary conversion event** as named in `clients/<slug>/context.md`.

Not to a vanity metric. Impressions, reach, follower count, keyword count, "brand awareness" and "engagement" are not conversion events. If the link to the conversion event is indirect, say how many steps away it is and what the intervening assumption is.

## NEEDS DATA

A list, or the single word `none`.

Every number the work would have needed and did not have. Every `[NEEDS DATA: …]` marker left in the output, repeated here so the operator sees them without re-reading the deliverable. Every claim that needs client confirmation before it ships.

This block existing is what stops the system inventing figures. An empty-looking run with six honest gaps is worth more than a confident one with six invented numbers.

## NEXT

**One** action. Not a list.

Name the owner — the operator, the client, a named agent, or a named contact from `context.md`. If the next action is blocked on something in NEEDS DATA, say which item.
